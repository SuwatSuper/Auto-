# แก้ false-positive ในรายงานสรุปต่อบริษัท (company_summary)

แก้เฉพาะ "ชั้นรายงาน" (advisory) — `code_labels.py` / `super_ultra_viewer.py` เท่านั้น
ไม่แตะ engine ตรวจ/กฎ/golden hash. เทสเดิมผ่านครบ (รวม `test_super_ultra_viewer.py`).

## 1. มี master แล้ว แต่ช่องชื่อบจ. ขึ้น "ไม่มี master ตรวจไม่ได้"
อาการ: ใส่ ภ.พ.20 แล้ว แต่บริษัทที่ชื่อในบิลเว้นวรรคต่างจากทะเบียนแค่ "ช่องว่างเกิน"
(เช่น `บริษัท  เมฆาเจริญ` มี 2 เว้นวรรค) กลับโชว์ว่าไม่มี master.

สาเหตุ: `CMP004` (เว้นวรรคไม่ตรง) ถูกจัดเลน `master` → viewer แปลเป็น
"ไม่มี master ตรวจไม่ได้" ทั้งที่ตรวจกับ master เจอแล้วและชื่อตรง (ต่างแค่ช่องว่าง).

แก้: ย้าย `CMP004` ไปเลน `review` → ช่องชื่อบจ. ขึ้น "ตรง" (ช่องว่างเกินไม่ใช่ข้อผิดพลาด).

## 2. บิลที่อ่านวันที่ไม่ได้ ถูกแยกเป็นบล็อก "ไม่ทราบเดือน"
อาการ: บิล 1 ใบอ่านวันที่ไม่ติด → ถูกตัดออกเป็นกลุ่ม "ไม่ทราบเดือน" แยกต่างหาก
ทั้งที่เลขที่เอกสารบอกเดือนชัด (เช่น `IV6905000850` = งวด 05/69).

แก้: เพิ่ม `_period_from_iv()` — เมื่อบิลไม่มีวันที่ ให้เดาเดือนจาก "งวดที่ฝังในเลขที่เอกสาร"
(ตรรกะเดียวกับ `detect_iv_period_mismatch`). บิลจึงเข้ากลุ่มเดือนที่ถูกต้องและรวมยอดได้.
อ่านงวดจากเลขไม่ชัดจริง ๆ ค่อยขึ้น "ไม่ทราบเดือน" (กันเดามั่ว).

## 3. รหัสไปรษณีย์ขึ้นซ้ำ 2 บรรทัดต่อบิล
อาการ: `ADDR001` + `ADDR005` ฟ้องรหัสไปรษณีย์เรื่องเดียวกัน → โชว์ซ้ำ 2 บรรทัด/บิล.

แก้: ยุบให้เหลือ 1 จุด/บิล (เก็บอันที่บอก "ทะเบียน xxxxx") + คำสั้น "รหัสไปรษณีย์ไม่ครบ".

## 4. ข้อความ "running ลำดับรายการสินค้า" ให้สั้น เข้าใจง่าย ไม่มีเครื่องหมายพิเศษ
เดิม `ITM002/013/014` โชว์ดิบ เช่น `ลำดับซ้ำ: [5]`, `ลำดับขาดหาย (ฟันหลอ): [3]`,
`ลำดับไม่เรียง: #5→#3` และมี `ลำดับที่ ?` โผล่.

แก้คำใหม่ (ไม่มี `# [ ] : → ? ( )`):

| กรณี | ข้อความใหม่ |
|------|-------------|
| ลำดับซ้ำ | `ลำดับที่ 5 ซ้ำกัน` / `ลำดับที่ 5 และ 7 ซ้ำกัน` |
| ลำดับขาด | `ขาดลำดับที่ 3` / `ขาดลำดับที่ 3 และ 7` |
| ขาดเยอะ | `ลำดับสินค้าขาดหลายรายการ` |
| ไม่เรียง | `ลำดับสินค้าไม่เรียงกัน` |
| ไม่เริ่มที่ 1 | `ลำดับสินค้าไม่ได้เริ่มที่ 1` |
| เว้นช่วงผิดปกติ | `ลำดับสินค้าเว้นช่วงผิดปกติ` |

ป้ายช่อง (label) ของ `ITM002/013/014` รวมเป็น `ลำดับรายการสินค้าผิด`.

# รอบ 2 (08.06.69) — แก้ที่ชั้น parser/address (เคส SSN + เอสที กิจมั่นคง)

## 5. "ห้องเลขที่ 104" ถูกเข้าใจผิดเป็น "บ้านเลขที่"
อาการ: ภพ.20 มี `ห้องเลขที่ 104 ... เลขที่ 303/1` แต่ระบบฟ้อง
`ที่อยู่ไม่ตรงทะเบียน: เลขที่ไม่ตรง (บิล: 303/1 / ทะเบียน: 104)` ทั้งที่บ้านเลขที่ตรงกัน (303/1).

สาเหตุ: regex `house_no` (`เลขที่\s*(\S+)`) ไปจับ "เลขที่ 104" ที่อยู่ใน "ห้องเลขที่ 104" (เลขห้อง).

แก้: `core_utils.parse_address_input` → `(?<!ห้อง)เลขที่\s*(\S+)` (ไม่จับเลขห้อง)
→ บ้านเลขที่ทะเบียน = 303/1 ตรงกับบิล → ที่อยู่ขึ้น "ตรง".

## 6. SSN: เลขที่เอกสาร/วันที่/งวด ผิดทั้งไฟล์ (อ่านบิลเก่าที่ค้างในเทมเพลต)
อาการ: ทุกชีตในไฟล์ SSN โดนอ่านเป็น `IV65060610 / 28-06-2022` (มิ.ย. 65) เหมือนกันหมด
→ แยกเป็นบล็อก `65.06` + ฟ้อง IV ซ้ำ/ชีตไม่ตรงวันที่/งวดไม่ตรง ยาวเหยียด.

สาเหตุ: แต่ละชีตมี "บิลเก่าค้างจากเทมเพลต" (คอลัมน์ 16: IV-65-060610 / 28-06-2022 เหมือนกันทุกชีต)
วางคู่กับ "บิลจริง" (คอลัมน์ 18: IV-69-05xxxx ตรงวันของชีต). header scan หยิบบิลเก่า (คอลัมน์ซ้าย) มาแทน.

แก้: เพิ่ม `_pb_prefer_period` ใน `parser_p2` — เมื่อในหัวบิลมีเลขที่เอกสารอ่านงวดได้ ≥2 งวด
และตัวที่หยิบ "ไม่ตรงงวดชื่อไฟล์" → เลือกเลขที่เอกสาร+วันที่ที่ "งวดตรงชื่อไฟล์" แทน
(ชีตปกติบิลเดียว/งวดตรงอยู่แล้ว = no-op สนิท → golden ไม่ขยับ, เทสผ่าน 52/52).

ผลหลังแก้: SSN อ่านเป็น `IV69050xxx / พ.ค. 2569` ถูกต้อง รวมกับไฟล์ TSH เป็นบล็อก `69.05` เดียว
(13 บิล) — ไม่มี `65.06` ลวง, ไม่มี IV ซ้ำ/วันที่ผิดแล้ว.

หมายเหตุ: ต้องตั้งชื่อไฟล์ให้มีงวด เช่น `SSN 69.05(3).xls` (ระบบอ่านงวดจากชื่อไฟล์เพื่อเลือกบิลที่ถูก).

# รอบ 3 — whitelist คำสะกดชื่อสินค้าที่เป็น false positive (ตามที่ผู้ใช้เลือก: แก้เฉพาะคำที่ผิดจริง)

ระบบยังเช็คคำสะกดชื่อสินค้าเหมือนเดิม แต่ "คำที่ถูกต้องอยู่แล้ว" ของผู้ใช้ถูก whitelist
(ไม่ฟ้องอีก) — เช็คคำผิดจริงคำอื่น ๆ ยังทำงานปกติ. golden ไม่ขยับ (เทสผ่าน 52/52).

## 7. เหล็กเพลา ถูกฟ้องว่าน่าจะเป็น เหล็กเพลท (ITM011 fuzzy)
'เหล็กเพลา' (steel shaft) เป็นสินค้าจริง คนละตัวกับ 'เหล็กเพลท' (steel plate) แต่หน้าตาคล้าย 88%
→ เพิ่ม 'เหล็กเพลา','เพลา' เข้า CONSTRUCTION_DICT → ระบบรู้จักว่าเป็นคำถูก ไม่ฟ้อง.

## 8. ปี๊ป / บล๊อก ถูกฟ้องว่าสะกดผิด (ITM010 THAI_TYPO_PATTERNS)
'ปี๊ป' (ปี๊บทินเนอร์) และ 'บล๊อก' (อิฐบล๊อก) เป็นคำการค้าที่ผู้ใช้ยืนยันว่าถูก (รอบ 1 ลง "ตรง")
→ ลบ pattern 'ปี๊ป'→'ปี๊บ' และ 'บล๊อก'→'บล็อก' ออกจาก THAI_TYPO_PATTERNS.

หมายเหตุ: 'ปี๊ป'/'บล๊อก' ตามพจนานุกรมจริง ๆ คือ 'ปี๊บ'/'บล็อก' (เป็นรูปแปร) — whitelist ตามที่ผู้ใช้ระบุ
ว่าถูก ; ถ้าต้องการให้กลับมาเช็คเข้มอีก แจ้งได้. ส่วนคำผิดจริงอื่น (เช่น มั้วน→ม้วน, เจียร์→เจียร,
ปลายสว่าง→ปลายสว่าน) ยังฟ้องเหมือนเดิม.

## ผลรวมหลังแก้ทุกไฟล์ที่ส่งมา (KRR/SHS/SBT/TSH/CHM/SSN + TSH รอบ 2)
ทุกบริษัทขึ้น "รายการสินค้า : ตรง" ; เหลือฟ้องเฉพาะของจริง:
  • โฟลว์ริช: รหัสไปรษณีย์ไม่ครบ (บิลลง 1120 ที่ถูก 11120) — ฟ้องถูกต้อง
  • เอสที: ชีต 3 แต่บิลลงวันที่ 4 — ขึ้น "ตรวจตาเพิ่ม" (ของจริง ให้คนเหลือบตา)
