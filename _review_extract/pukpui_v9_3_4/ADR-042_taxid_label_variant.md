# ADR-042 — รองรับ label เลขภาษีฟอร์ม "เลขที่ประจำตัว…" + จัดกลุ่มผิดแบบ (FIX-TAX-LABEL v9.3.3)

สถานะ : ACCEPTED — 17.06.2026
บริบท : ผู้ใช้ส่งไฟล์จริง 5 ไฟล์ (CHM, HSH, SHS, SSN, TKH — ผู้ซื้อ "บริษัท ซันไรส์ คอนสตรัคชั่น จำกัด"
เลขภาษี 0135560008574) ให้ตรวจว่าระบบอ่านได้ครบไหม. 4 ไฟล์อ่านครบถูกต้อง แต่ **HSH อ่านเลขภาษีไม่ได้
ทั้ง 9 บิล** → ลามเป็น false CRITICAL 18 จุด.

---

## อาการ (HSH 9 บิล)

ระบบอ่าน `tax_id = ''` (ว่าง) ทั้งที่ไฟล์มีเลขภาษีจริงในเซลล์ `[7,0]`:

```
'เลขที่ประจำตัวผู้เสียภาษี  0-13556-0008-57-4'   →  0135560008574 (13 หลัก, ถูกต้อง)
```

ผลลามปลายน้ำ (รัน rules จริง):
- **TAX001 CRITICAL ×9** : "ไม่พบเลขภาษี" (false — เลขมีจริง)
- **CMP001 CRITICAL ×9** : เมื่อไม่มีเลขภาษี ตัวจับคู่ master ตกไปใช้ fuzzy "ชื่อ" → จับผิดเป็น
  "บริษัท ฉี อัน คอนสตรัคชั่น กรุ๊ป" (fuzzy 73%) → ฟ้องชื่อไม่ตรง (false)

เทียบ CHM (เลขภาษีอ่านได้): `master_key='(ไม่พบใน master)'` เฉย ๆ ไม่มี CMP001/TAX001 →
ยืนยันว่า 18 CRITICAL เป็น **ปลายน้ำของรากเดียว** = อ่านเลขภาษี HSH ไม่ได้.

## Root cause (รากของปัญหา)

2 ปัจจัยรวมกัน ทำให้ทุก path ของการดึงเลขภาษีพลาด:

1. **Label มีคำว่า "ที่"** : HSH ใช้ "เลขที่ประจำตัวผู้เสียภาษี" (มี 'ที่') แต่ `_TAXID_KW` มีแค่
   "เลขประจำตัวผู้เสียภาษี" (ไม่มี 'ที่') — ไม่ใช่ substring กัน → keyword path A ใน
   `_extract_taxid_safe` หาไม่เจอ.
2. **จัดกลุ่มเลขผิดแบบ** : "0-13556-0008-57-4" = 1-5-4-2-1 แต่ regex มาตรฐาน
   `\d[-\s]?\d{4}[-\s]?\d{5}[-\s]?\d{2}[-\s]?\d` คาด 1-4-5-2-1 → ไม่ match.
   และเลขไม่ติดกัน 13 ตัว (มีขีดคั่น) → path B (13 หลักติดกัน) ก็ไม่ match.

→ ทุก path fail → tax_id ว่าง.

## Decision — ทางแก้ที่เลือก (minimal, golden-neutral)

เพิ่ม label variant ลง `_TAXID_KW` (config.py):

```python
'เลขที่ประจำตัวผู้เสียภาษี','เลขที่ประจําตัวผู้เสียภาษี'
```

ทำไมพอ: keyword path A ใน `_extract_taxid_safe` เป็น **grouping-agnostic** — เมื่อเจอ label
แล้วจะดึงข้อความตามหลัง ตัด non-digit ทิ้ง แล้วเช็คว่าเหลือ 13 หลักไหม. ดังนั้นพอ label ตรง
ก็รองรับการจัดกลุ่มผิดแบบ (1-5-4-2-1 หรืออื่น ๆ) ได้ทันที โดยไม่ต้องแก้ regex grouping เพิ่ม.

ขอบเขตปลอดภัย: path A รับเฉพาะเมื่อ "หลัง label มีเลข 13 หลัก" → ไม่ over-match เลขสั้น/มั่ว.
`_TAXID_KW` ถูกใช้ที่เดียว (`_extract_taxid_safe`) → ผลข้างเคียงจำกัด.

## สิ่งที่ไม่ใช่บั๊กของระบบ (รายงานให้ผู้ใช้ทราบ)

- **HSH ชีต '24' : DOC001 "ชีต=24 แต่วันที่=20"** — เป็น **true positive**. เซลล์วันที่จริงในไฟล์
  (date-typed `[7,16]`) เท่ากับ 20/04 เหมือนชีต '20' (น่าจะ copy เทมเพลตชีต 20 มาทำชีต 24
  แล้วลืมแก้วันที่). ระบบอ่านตามไฟล์อย่างซื่อสัตย์ **และจับความผิดปกตินี้ได้ถูกต้อง** →
  ผู้ใช้ควรแก้ที่ไฟล์ต้นฉบับ. (ไม่แก้ที่ระบบ)
- **ITM004/ITM005/ITM015 (advisory)** — คำแนะนำเรื่องเว้นวรรคชื่อสินค้า/หน่วยนับ ระดับ INFO/WARNING
  ไม่ใช่การอ่านพลาด.
