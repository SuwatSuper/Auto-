# ADR-0001: Three-Layer Architecture

## Status: Accepted

## Context

We need a trading system that is testable, maintainable, and separates concerns between pure business logic and infrastructure.

## Decision

Use a strict three-layer architecture: Domain, Orchestration, Infrastructure. Each layer may only import from the same or lower layers.

## Consequences

- Domain code is fully unit-testable without mocks.
- Infrastructure can be swapped (e.g., in-memory bus vs Kafka).
- More boilerplate for ports/adapters but cleaner long-term.
